# Agent 三栏工作台

2026-10-08 恢复的开发需求与实现记录。入口仍为 `transmux-v2`，沿用 `data-v2/`，数据库中的 project 对应界面上的 Agent，无需重建已有工作区。

## 左栏：Agent 与资源

- `New Agent` 推荐不重复的名称；用户修改后不再自动覆盖。
- 可选择 Codex / CodeBuddy、实时模型列表和目标语言。默认选择返回列表的第一项；查询失败显示回退提示。
- 每个 Agent 有独立文档库和翻译资源库，切换时清空上一个 Agent 的附件、预览和产出。
- 文档库按登记文件的工作区相对路径展示目录树；任务原始记录按需加载。
- 翻译资源库只有两个一级分类：翻译风格、专有名词。风格与专有名词表须经人工审核才能用于翻译；已有术语配置保留查阅和编辑入口。

## 中栏：输入与任务

文档上传 / 从文档库附加及任务模板紧凑置顶，中间为统一背景的无气泡对话历史，输入框固定在中栏底部。右上角状态组件显示连接中、空闲、执行中、排队、待审核或需处理。文档库与翻译资源库嵌在各自 Agent 的展开节点下。

任务模板为：学习、翻译、排版、一致性检查、上传专有名词表。翻译资源、排版预设（原格式 / JCST / IEEE Access）和一致性检查原文通过弹层选择。预览使用独立弹层。

一致性检查按原译对照实现，检查漏译、误译、术语、人名和风格，不进行联网事实核查。项目译文自动使用持久化段落对应关系，支持未审核译文；外部译文需要在选项中明确选择同一 Agent 文档库中的原文。未选附件时使用最新已审核译文。

检查前保存输入快照，验证项目译文与对照记录一致，分批保存结果并传递已观察术语；核查引用必须是原译文的精确文本。证据不符时任务进入需处理状态，不发布报告。报告仅提出建议，不修改文件。无段落对照的外部原译文合计超过 24,000 字符时要求按章节拆分，不静默截断。

旧事实核查 API 和历史报告继续可用。

## 右栏：产出与审核

按文件状态自动同时展示未审核和已通过区域，无需切换；空区域自动隐藏。分类显示学习风格产出、翻译产出、排版产出和一致性核查报告。专有名词表和已有其他报告各自保留分类。待审核产出在所属任务的对话历史中高亮，提供审核通过、忽略和适用的修改入口；右栏提供预览、下载与跳转审核。

所有可发布产出均有持久化人工审核记录，自动任务成功不代表审核通过。排版 DOCX/PDF 分别审核，内部 manifest 留在文档库。旧排版文件与报告首次启动时补为未审核，已有审核状态保留。审核会校验文件摘要。

忽略状态持久化，保留文件和历史，不等于审核通过；被忽略的风格、词表不能用于翻译。可从历史或右栏折叠的“已忽略”区域恢复审核。已通过产出不能忽略。

## Token 用量与统一费用估算

每次 CLI 调用单独保存用量，按任务及 Agent 聚合；翻译、审校、修订、工具循环等调用均累计。任务结束后在对话历史显示输入、缓存命中输入、输出、总 Token 和预估费用；Agent 设置显示全部任务累计值，包含失败任务已经消耗的 Token。

统一采用 [Kimi K3 官方人民币价格](https://platform.kimi.com/docs/pricing/chat)，核对日期 2026-10-08：每百万 Token，未缓存输入 ¥20、缓存命中 ¥2、输出 ¥100。缓存写入按默认 5min 档（¥20）计入普通输入，跨引擎不假设 1h 缓存。费用是共同基准估算，不是 Codex / CodeBuddy 实际账单，不包含工具费用。

总输入包含缓存命中；估算公式为 `((输入 − 缓存命中) × 20 + 缓存命中 × 2 + 输出 × 100) / 1,000,000`。推理 Token 如已包含在输出中，不再次计数。每条调用保存计价快照和整数微元金额，聚合不逐项舍入。

Codex 使用终态 usage；CodeBuddy 优先使用终态 modelUsage，避免把流式消息和最终总量重复相加。无最终统计的中断调用保留已报告部分并标注不完整。完全缺失的用量显示未记录，不能当作零消费；不调用模型的任务可显示零。旧任务从完整的终态日志尽可能回填，并标注历史用量可能不全，不按文本长度伪造计费 Token。

## 资源弹层与逐条风格审核（2026-10-08）

Agent 下仅保留“文档库”“翻译资源库”入口，点击后在弹层展示目录和资源，不再展开占用第一栏。文件预览、配置编辑、附加文档继续可用。

新版学习任务先生成结构化规则 JSON，每条保留文档名、段落号和已校验原文引用。审核弹层默认全选，支持逐条勾选和全选/取消全选，至少选择一条。确认后仅将选中规则确定性写入 Markdown，不再调用模型改写规则；规则选择与全部出处持久化，原始候选 JSON 保留。生成文件直接标记为人工审核通过，可用于后续翻译。修订结构化风格也保留出处并重新逐条审核。历史整体风格保留原有审核方式，在弹层明确标注缺少逐条出处。

本轮验收：浏览器流程通过；全量测试 205 通过，仅既有旧风格调用次数断言失败。LAN 健康检查、资源弹层页面和结构化审核接口已确认上线。部署前数据库及源码备份位于 `build/style-rules-backup-20261008-172126/`。


## 模板自动提交与实时状态

点击任务模板先校验工作条件；学习、上传词表在校验后直接提交，翻译、排版、一致性检查在确认弹层选项后提交，不再需要点击对话发送。缺少文档、失效文件、上传未完成、多选不适用或排版产出未通过审核会显示持续警告；服务端也会在入队前校验实际文件存在。排版和一致性检查也必须明确附加文件，不再自动采用上一次译文。

顶部状态使用突出色块，显示实时阶段标题（翻译、审校、修订、排版等）及当前进度说明，同时显示排队数量。修订风格和词表时也会明确显示“修订中”。

本轮验证：18 项相关后端测试通过；浏览器覆盖缺少文档时阻止提交、模板自动提交、翻译阶段状态与进度详情、选项取消和桌面/手机布局。备份：`build/task-launch-backup-20261008-175057/`。


## 明确附件与语义排版（2026-10-09）

任务成功提交后清空本次附件及上传记录；任务完成不会自动附加输入或产出。后续任务必须由用户重新选择文件，服务端同样拒绝缺少附件的排版/核查请求。右栏产出卡片、对话审核卡片均提供“附加到本次任务”，文档库入口继续支持附加。此操作仅选择文件，不代表审核通过；排版已生成产出仍需先审核。

选择 JCST 投稿版、JCST 出版版或 IEEE Access 后，排版调用语义引擎；“保留原格式（不重写引文）”继续提供字节不变的原样导出。语义引擎识别每个文档块的角色，提取有原文依据的参考文献元数据，匹配数字、作者年份与“见某文献”等自然语言锚点。稳定引用 ID 与原文位置经过程序校验，最终编号按正文/表格中的首次出现位置确定，同一文献重复引用复用编号。没有正文锚点的文献保持原始相对顺序放到参考文献末尾，绝不删除；跨段条目保留为同一文献。

输出含 DOCX、PDF（转换成功时）和独立待审核的“排版与引文处理报告”。报告列出参考文献总数、未找到锚点数量与明细、原编号到新编号映射、每处锚点改写和待复核项。未知数字锚点用 `[?原编号]` 明示，避免意外指向新编号；有歧义的自然语言引用保留并列入报告。元数据不能无损拆解时保留原条目文字，仅更新编号，不补造 DOI/作者/年份。主文档正文、题注和表格参与匹配；页眉页脚、脚注和尾注不计入该扫描范围，报告有明确说明。

原文快照、结构、Agent 响应和引用关系保存在任务目录；排版在副本上执行，非引文正文和 OOXML 资源保留。包含无法安全修改的动态字段、混合内联对象、参考文献分节符时停止发布并保留任务材料。单个结构块上限 16000 字符；完整参考文献索引上限 65000 字符，超限明确提示拆分，不静默截断。

模板依据与渲染规则见 [排版文档](layout-export.md)。Codex 与 CodeBuddy 已分别用 JCST 投稿版和 IEEE Access 完成真实验证：4 条参考文献、3 处锚点（含表格内自然语言引用），准确识别 1 条未引用文献并保留在末尾，同时生成 DOCX/PDF/报告。验收文件保存在本机 `build/semantic-live-codex-1791475649/` 与 `build/semantic-live-codebuddy-1791475649/`。


### 引文位置校验修复（2026-10-09）

语义协议升级到 v2。非引文数组仅用于排除可能被数字引用补扫误认的方括号表达式，每项必须带段落、原文片段和 1 起始的 occurrence，只排除指定出现位置。普通年份不进入占位区，避免 `1950` 误伤 `Carnap-1950` 等作者年份引用；实际引文范围与非引文排除表分别维护。旧结果仅在位置唯一时兼容数字排除记录，位置含糊时要求重新识别，不再把所有同文片段一起排除。真正交叉重叠的两个引文仍然拒绝改写。

验证：20 项相关测试通过，覆盖年份/作者年份并存、同段相同 `[1]` 分别表示数组和引文、无效 occurrence 与真实重叠；回放此前失败批次的 5 个实际锚点全部通过位置校验。未修改或自动重跑原失败任务。部署前备份：`build/anchor-position-backup-20261009-075946/`。

### 译文原文对照审核

译文的预览与“原文对照审核”入口使用已保存的段落对应记录，左侧原文、右侧当前译文；合并或拆分的段落按同一组展示，窄屏逐组上下排列。对照窗口支持审核通过、忽略及修改此版本。无对照记录时明确提示并禁用窗口内的通过按钮，不按段落序号猜测对应关系。

排版产出文件统一命名为“原文文件标题-模板-产出类型.扩展名”，覆盖 DOCX、PDF、处理报告和 manifest。译文及其修订版优先沿对照/审核版本记录查找原始上传文件名；无法追溯时使用所选文档文件名。文件标题会清理路径字符并截短，历史产出不重命名。
