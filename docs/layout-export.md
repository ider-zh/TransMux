# 排版与导出

## 已确认的产品范围

- 两个入口：完成的译文；独立上传的 DOCX 文稿。首版不处理独立 PDF 排版。
- 默认保留原文档格式、引用样式及内容；直接下载 DOCX 不经过重写。
- 选择期刊预设后才应用排版、引用和参考文献规则。首批预设计划为 JCST 和 IEEE Access，按具体官方投稿模板及其版本管理。
- 官方预设不可直接修改，可复制为标注“自定义”的版式。
- Agent 识别结构、匹配引用、补全文献信息；确定性的程序负责字体、分栏、编号、参考文献格式与文件生成。
- 每个项目维护独立文献库，同项目文档复用。无需用户额外上传 BibTeX 或 RIS。
- 唯一标识匹配、无冲突的缺失字段可自动补全；候选歧义及冲突交给用户确认。记录字段来源和修改历史，保护人工修改。
- 外部检索只发送查找文献所需的元数据，不发送整篇稿件。不得编造文献事实。
- 保留图片、表格、公式；不能可靠排版时列出问题，不擅自重写内容或删除对象。
- 先生成预览与检查结果，再下载 DOCX/PDF。有未解决问题允许导出草稿，不宣称完全符合期刊要求。
- 所有生成结果独立保存版本，不改写已有导出。

## 第一阶段：已实现

### 用户界面

项目文件区的“排版与导出”折叠入口支持上传独立 DOCX。文件列表中的 DOCX 原文、译文、对话修改版和独立文稿可打开导出面板；独立文稿不进入待翻译文档选项。

面板提供原 DOCX 直接下载、生成预览、历史版本选择、PDF 预览、DOCX/PDF 和检查记录下载。面板占满窗口，PDF 预览、文档结构、检查结果使用独立标签页；PDF 及结构列表各自占满剩余空间。导出历史及下载按钮始终位于面板工具栏，另提供新标签页打开 PDF。手机端也使用标签切换。

当前提供“保留原格式”“IEEE Access · 投稿排版草稿”和“JCST · 出版排版草稿”。文献识别、外部补全和自定义版式尚未实现，界面明确区分排版草稿与投稿合规。

### 数据和任务

- `files.kind=manuscript` 表示独立排版文稿，原文件放在项目 `sources/`。
- `jobs.kind=layout` 复用项目内串行、项目间并行的调度器，不启动 Agent，不构建 RAG。
- `layout_exports` 记录项目、输入文件、任务、检查快照和创建时间。
- 生成时将输入 DOCX 原样复制到 `data/exports/<project>/<export>/document.docx`；对发布译文使用已有的不可覆盖下载快照。
- 同一目录保存 `document.pdf`（成功时）、`manifest.json` 和内部转换日志。转换临时配置在完成或取消后删除。
- 检查记录包含原文件标识、模板 ID/版本、DOCX SHA-256、PDF SHA-256/页数、转换引擎、检查项与提示。
- 保留原格式时 DOCX 不经重新序列化；所有模板的 PDF 转换前后都验证 DOCX SHA-256 相同。输入文件后续变化不影响已经保存的导出版本。
- 先生成文件，再原子发布目录和保存数据库记录；数据库失败撤回目录。取消任务不发布半成品。
- PDF 转换失败仍发布 DOCX 快照，任务标记“需处理”，用户可以查看原因并重试。重试创建新版本。
- 删除项目时同时清理导出记录和文件，沿用项目忙碌检查与删除回滚机制。

### PDF 转换

使用本机 LibreOffice，默认从 PATH 查找 `libreoffice` 或 `soffice`；可以通过 `TRANSMUX_LIBREOFFICE` 指定可执行文件。每次转换使用独立配置目录，120 秒超时，取消时终止该次转换进程组，不操作用户已有的 Office 进程。

命令参数依据 [LibreOffice 官方文档](https://help.libreoffice.org/latest/en-GB/text/shared/guide/start_parameters.html)，采用 `--headless --convert-to pdf:writer_pdf_Export` 和独立 `UserInstallation`。

DOCX 包中有宏、嵌入对象、外部资源或外部数据字段时，保留原 DOCX 并提示处理，首阶段不进行自动 PDF 渲染。这是应用层检查，不是任意恶意 Office 文档的沙箱；当前服务仍适用于可信局域网。

PDF 字体替代、分页、复杂对象可能与 Word 有差异。第一阶段只校验 DOCX 原样保留、PDF 可读取及页数，不进行内容等价、视觉质量或期刊合规检查。应在预览中审阅图表、公式和分页。

### API

- `GET /api/layout/capabilities`：当前支持的模板、是否检测到转换程序。
- `POST /api/projects/{pid}/files?kind=manuscript`：上传独立 DOCX。
- `POST /api/projects/{pid}/jobs`：`{"kind":"layout","file_id":"…","template":"original"}`。
- `GET /api/projects/{pid}/files/{fid}/exports`：该输入文件的导出历史。
- `GET /api/projects/{pid}/exports/{eid}/{docx|pdf|json}`：下载某版本。
- PDF 地址加 `?preview=true` 返回 inline，可由同源页面嵌入。

下载和查询始终验证项目归属。PDF 不可用时不会提供损坏的下载链接。

## 后续实施顺序

1. **第一个官方预设流程已接通**：IEEE Access，详细范围见下节。复杂对象和未完成文献核验进入草稿检查清单。
2. **项目文献库**：文献实体、正文引用标识、原始条目、字段来源和人工确认保护；Agent 只对歧义部分提出结构化候选。添加待审查列表和修改记录。
3. **文献补全和引用渲染**：按 DOI 等检索元数据，缓存结果；唯一匹配自动补全，歧义交用户。引用使用实体标识关联，最终编号和参考文献按模板统一生成。每次导出冻结文献快照。
4. **自定义版式**：JCST 第二个官方预设已接通；后续开放从官方预设复制和调整字号、字体、分栏、引文样式。

每阶段沿用串行任务进度、版本保存与检查面板。实现前核实官方模板细节，不将普通双栏布局标记为官方投稿格式。

## 第二阶段：IEEE Access 投稿排版草稿

来源为 [官方投稿页](https://ieeeaccess.ieee.org/authors/submission-guidelines/) 提供的 [Access-Template-2024.docx](https://ieeeaccess.ieee.org/wp-content/uploads/2025/08/Access-Template-2024.docx)。模板内部日期为 2024 年 4 月；2026-09-16 核实该文件仍由投稿页链接。记录文件 SHA-256，规则版本为 `2024.04-r1`。

`scripts/extract_access_template.py` 从官方文件提取格式属性，不包含示例正文、标识、DOI 或出版日期占位符。`transmux/templates/ieee-access.json` 随包发布，运行时无需联网。官方模板用于稿件准备；应用只分发提取的格式规则，不分发示例稿件，也不代表 IEEE 认证。

### 已实现

- 提取并应用官方模板的版心：页面 11520 × 15660 twips，左右边距各 740 twips；前置信息单栏、正文双栏，栏距 400 twips。
- 标题、作者、机构、摘要、关键词、正文、三级标题、图题、表题、参考文献及作者简介使用各自样式。标题为 Helvetica 22 pt，正文为 Times New Roman 10 pt；服务器缺少字体时 PDF 渲染器可能替代。
- 保留原来的正文、引用、编号、强调、公式、表格、图片及文件关系。只改 `word/document.xml` 和 `word/styles.xml`，其他 ZIP 项保持原始字节。内容签名忽略排版属性，但保留文字、对象、字段和关系标识，检测意外改写。
- 保留原有列表的直接编号及样式继承编号；本阶段不新增、重排标题编号或文献编号。
- 采用稳定于同一输入快照的文档块 ID，前端可修正段落类型。使用输入 SHA-256 防止把旧结构修正应用到变化后的稿件。
- 有缺失、推测结构或复杂对象时给出带文档块位置与文字片段的检查项。类型修正只影响下一次生成，历史版本保持原样。
- 输入快照保存为该导出目录中的 `input.docx`，输出为 `document.docx`；检查记录存储规则来源、输入/输出摘要、结构和检查结果。
- 文献核验尚未实现，因此 IEEE Access 输出始终为 `draft`，任务状态为 `needs_attention`。DOCX/PDF 可下载，不能解释为自动通过全部投稿要求。

### 当前边界

结构识别依据显式 Word 样式和摘要/参考文献等标签，无法确定的前置信息不推测作者姓名；用户通过“文档结构”修正。当前不调用 Agent 识别文献或补写稿件内容。

复杂表格、浮动图、公式保留原对象与尺寸并标记检查，尚不自动解决跨栏布局；页眉、页脚、脚注保留原稿样式。当前不把作者年份制引用自动变为数字引用，不自动核验或重写参考文献条目、补充作者简介，亦不保证投稿合规。

新增 API：`GET /api/projects/{pid}/files/{fid}/structure` 返回块类型和输入摘要。模板任务提交 `template: "ieee-access"`、`source_sha256`，可选 `roles: {"b00002":"authors"}`。未读取输入结构时拒绝提交该模板任务。


## JCST 出版排版草稿与全窗口工作区

2026-09-16 核对 [SciOpen 的 JCST 官方作者页](https://www.sciopen.com/journal/join_journal/submission_guidelines?id=1574306362798288898&issn=1000-9000) 提供的 `JCST Publish Template (Word).docx`。文件内部修改日期为 2022-06-28，规则版本 `2022.06-r1`，同时记录源文件 SHA-256。JCST 区分 Submit 和 Publish 模板，本次实现的是 **Publish 出版排版草稿**，不代表投稿审稿模板。

`scripts/extract_jcst_template.py` 提取代表段落的继承及直接段落属性、版心和栏数；字号、字体按官方文件的明确标注整理。该模板含大量通用样式及直接格式，不能仅按 Word 样式名称映射。图题按模板文字明确指定的 10 pt（其样例运行格式存在继承差异）；不复制示例正文、页眉、基金、作者、出版时间或文献。规则在 `transmux/templates/jcst.json` 中随包发布，无需 Agent 或运行时联网。

- 纸张 11907 × 16840 twips（约 A4），上边距 1474、下边距 765、左右边距 839 twips。前置信息单栏，正文双栏，栏距 421 twips。
- Times New Roman：标题 16 pt 加粗，作者/机构/摘要/关键词/正文/参考文献 12 pt，图题与表题 10 pt。机构和三级标题斜体；正文 1.5 倍行距。中文字符字体为模板指定的宋体，渲染器可能替代缺失字体。
- 复用结构类型修正、输入 SHA-256 校验、内容/资源保留、独立导出版本和检查记录流程。API 使用 `template: "jcst"`，同样必须提供 `source_sha256`。
- 引文及参考文献的内容、编号、局部强调沿用原稿；不自动把作者年份引用转换成方括号数字，也不核验元数据。复杂对象和页眉页脚的处理边界与 IEEE Access 相同，因此导出仍标为草稿。
- 全窗口面板提供“PDF 预览 / 文档结构 · 可修正 / 检查结果”。结构列表不再限制为 320px，段落片段最多显示接口提供的 600 字符；类型选择、标签切换保留本次修改。切换标签不会重新请求或重载 PDF。默认仍为保留原格式。
