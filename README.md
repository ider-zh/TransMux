# TransMux

基于 Codex CLI / CodeBuddy 的轻量文档翻译 harness。项目绑定 Agent，Agent 管理会话上下文；TransMux 负责工作区文件、语义检索、任务排队、审校循环和 DOCX 发布。

## 启动

需要 Linux / macOS、Python 3.11+，并安装、登录至少一个 CLI：`codex` 或 `codebuddy`。前端为原生 HTML / CSS / JavaScript，无 Node 构建步骤。

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e '.[local-rag,dev]'
transmux
```

打开 http://127.0.0.1:8000 。首次进入必须创建项目并选择 Agent。已有项目会在服务重启后恢复，不会每次创建新项目。CLI 的“已安装”状态仅表示能找到可执行文件；登录或模型错误会在任务日志中显示。

如果已有兼容 `/embeddings` 接口的服务，可以只安装 `pip install -e '.[dev]'`，然后配置下文的向量接口。

### 局域网访问

在受信任的局域网内，将监听地址与允许的 Host 一起配置为本机局域网 IP。例如：

```bash
TRANSMUX_HOST=192.168.1.220 \
TRANSMUX_ALLOWED_HOSTS=192.168.1.220,localhost,127.0.0.1 \
PORT=8765 transmux
```

同一局域网设备打开 `http://192.168.1.220:8765`。IP 变化后需同步更新配置；当前服务无登录，能访问该端口的设备可操作项目与 Agent。

## 使用流程

1. 创建项目，选择 Codex CLI 或 CodeBuddy，并从下拉框选择目标语言 English / 简体中文，默认 English。Agent 与目标语言均在数据库层锁定，项目中不可修改；旧项目自动升级为 English，现有配置与历史保留，下次提取时按新规则更新。
   创建时可选择模型，之后可点击右上角“Codex / CodeBuddy · 已绑定”区域，在弹出面板中选择模型并点击“应用模型”。候选来自本机 Codex 模型缓存或 CodeBuddy CLI 帮助，也可输入自定义模型 ID；是否可用由 CLI 和账号权限决定。留空表示沿用 Agent 会话 / 默认设置，不保证重置已恢复会话的模型。修改保留会话上下文，排队任务开始时读取新设置，运行中任务的所有翻译与审校步骤继续使用原模型；配置记录在任务的 `agent.json` 中。
2. 上传参考语料，支持一次多选或分次追加 PDF、DOCX、UTF-8 TXT / Markdown，每个文件不超过 25 MB。语料区逐份显示文件名与上传时间，可下载或确认删除指定文档。删除后移除原文件、提取文本和旧索引；下次翻译或召回时自动重建，已有风格、术语、译文与任务历史保留。
3. 点击“更新风格与术语”，按段落筛选项目目标语言语料，更新 `style.md` 的通用规范和 `terms.json` 的目标语言术语（首选术语、含义、使用规范与语料出处）。单语语料不会推测双语对照。系统给语料段落显式编号，校验时兼容引号、连字符和空白差异；编号错误但可在本批唯一定位的术语会修正引用，无法核实或引用不明确的条目单独跳过，不中断风格更新。每批原始结果和校验报告保存在任务记录，进度中显示修正与跳过数量。术语管理有“专业术语”“翻译对照”“人名”三个标签页，支持表格编辑、增删、批量导入和独立历史恢复；JSON 编辑放在高级选项中。输入后自动保存，必填字段为空时暂不保存。手动改动标记为“用户指定”，自动更新不会覆盖；删除记录也会保留，避免下次提取重新添加。
4. 风格和目标语言术语更新后，系统自动同步目标语言参考索引，无需手动构建。通过“测试召回”查看同语言的相似段落、来源、段落编号和余弦相似度。索引更新失败时保留已生成的风格与目标语言术语，展示失败状态与重试入口。
5. 上传待翻译文档，目标语言只读显示项目设置。可切换“启用 RAG 参考”（默认开启，按项目记住选择），选择审校上限后翻译。开启时每批原文仅检索目标语言参考；关闭时使用项目风格与关键词表，不调用向量服务。所有批次审校通过后才发布 DOCX。醒目的实时状态卡显示准备、检索、翻译、审校、修订、导出等阶段，以及当前段落范围和已通过审校数量；保持批处理，不增加逐段 Agent 调用。
6. 翻译调用可同时返回有原文与译文依据的对照，由现有审校步骤一起验证，不增加模型调用。段落编号包括标题；编号错误时，仅在原术语和译法能共同定位到本批唯一的原文/译文段落对时校正。匹配歧义、无证据或语境语言错误的对照单独跳过。审校的 `passed/issues` 只判断正文质量，`mapping_issues` 单独标记不宜积累的对照；不要求术语表穷举，缺少对照不触发整批重译，正文中的错译、漏译、术语错误仍须修订。整项翻译审校通过后只将有效对照写入 `mappings.json`，显示“新增 N 条翻译对照”，点击可打开对应标签页。原始候选、段落号校正、跳过原因及术语审校记录都保存在任务目录。
7. 从文件区下载译文；通过对话提出措辞、内容或格式调整。对话修改版单独标注“未重新自动审校”，不会冒充已审校版本。

开启 RAG 但缺少目标语言参考段落时继续翻译，明确提示采用通用目标语言风格、本次未使用 RAG。有目标语言语料而索引缺失、过期或格式升级时自动重建；修复失败则暂停，用户可重试或关闭 RAG 后重新提交。达到审校轮次上限仍未通过会停在“需处理”，草稿、反馈与输入快照可在“任务记录”下载，亦可通过对话继续处理。

风格与三个术语标签页均提供“历史快照”：选择版本可预览完整内容并恢复。历史记录在 SQLite 中持久化，保存时间、来源与关联任务。手动保存、提取更新、任务结束时发现的 Agent 修改（包括失败任务）都会保留快照；页面读取时也记录检测到的工作区变更，相同内容连续保存不重复生成。恢复是一次新的修改，不删除旧历史，并检查并发版本冲突。升级时将现有配置保留为初始历史，不会虚构升级前的编辑记录。外部工具在两次检查之间多次写入的中间态不会逐次记录。

所有内置 Agent 任务指令使用英语；用户请求、原文、引用语料和旧配置作为数据保留原语言。新项目的初始风格按目标语言生成。风格标题和正文、术语含义与使用规范以及翻译对照的语境说明使用项目目标语言，源术语保留原语言。自动风格按当前语料重新汇总，人工要求独立保留并优先适用。升级不会直接覆盖现有配置。

保存前进行本地语言检查：忽略引号内引用、反引号、代码块和 Markdown 引用块，允许正文中的少量外语名称；检查使用文字比例和保守的语言识别，不额外调用 Agent，也不是绝对准确的语义判定。风格语言不合规时保留候选，任务标记为需处理；术语说明不合规时逐条跳过并记录。手动保存与历史恢复也受检查，恢复不符合当前语言规则的旧版本时需要先改写。对话修改风格通过候选文件提交给 harness 校验后保存。

升级保留原 `glossary.md` 及全部历史。可识别的显式双语表格导入翻译对照并保护为用户指定，来源注明未重新验证；其他旧文本完整保存在“查看旧关键词原文”档案中，不当作有效术语自动注入任务。旧版原文件历史仍通过 `/config/glossary/history` 保留。恢复术语历史后，其中条目按用户指定保护。

工作空间底部的“工作空间设置”提供删除入口，需输入完整空间名称确认。删除会移除该空间在应用中的文件、已发布译文、索引、配置、历史和任务记录，不影响其他空间。空间有运行中/排队任务或正在上传解析文件时拒绝删除。删除操作不清理第三方 CLI 自行保存的会话或已有运维备份。文件先移入应用内临时目录，再提交数据库删除；数据库失败时恢复文件，清理异常会记录服务器日志。

## 术语与人名管理

翻译风格与术语上下分行，术语区占满主内容区宽度，可展开到接近全屏。支持搜索，以及已生效、待确认、已停用筛选；解释、收录理由与原文证据点击展开。

自动提取仅收录有具体一致性需求的表达：首选写法需要固定、存在专业歧义、缩写需要统一，或项目明确命名的概念。词形简单不是排除条件，但普通词义解释本身不是收录理由。比如只有 Script 的历史概念定义时应跳过；存在明确混用风险时，须提供限定语境和理由。Agent 负责语义判断，程序检查需求类别、理由、语境、语言和原文证据；这不是能够保证零误判的分类器。同词不同语境可并存，自动冲突成为独立待确认候选，不覆盖现有内容。

人名存入 people.json。明确的同语种原名或已有已确认对应可自动生效；新出现的跨语言对应保守进入待确认。原文不支持的全名、别名不推断；无法可靠确定译法时保留原文并继续翻译。正文可以依行文使用全名、姓氏或缩写，但不得混淆人物；参考文献中的作者排版仍由独立排版模块处理。翻译与现有审校同时关注人名，`people_issues` 单独处理不可靠的人名元数据，不因缺少可选元数据要求整批重译；实际正文中的人名错译仍须修订。不增加日常提取或翻译的调用步骤。

只有已生效条目进入常规任务提示词快照。待确认条目须检查写法后点“确认生效”；与已有条目冲突时明确提示替换。停用条目仍在表中，可筛选和恢复；删除与停用决策不会被下一次自动提取静默撤销。用户指定内容优先，所有修改保留历史。

批量入口支持 Excel/WPS 复制粘贴，以及 XLSX、UTF-8 CSV/TSV 导入，提供 CSV 模板。第一行是否为标题可切换；自动匹配列后可手动调整。XLSX 读取第一张工作表，不执行公式，公式需先转为值。限制为 2 MB、5000 条、30 列。预览可编辑，重复及冲突默认跳过；明确选择替换才覆盖同词同语境条目。保存采用版本检查，预览期间发生并发修改时拒绝应用旧预览。

“按新标准重新筛选”是用户主动发起的独立项目任务，只检查自动条目，不改动用户指定内容。完成后点“查看筛选建议”，可查看保留、调整语境、归入人名或停用建议，编辑并勾选后应用。应用前对三个术语文档一起检查版本；发生普通写入异常时回滚文件与历史记录。转入人名的条目先待确认，原术语停用而非删除。升级不自动清理旧条目，也不会在每次翻译前重复筛选。

## 原文与译文对照

翻译及审校完成后，项目文件中的译文旁出现“对照”入口。点击打开接近全屏的只读面板：宽屏左原文、右译文，按段落组成对排列并共用滚动条；窄屏每组上下排列。保留标题级别和表格位置标记，不进行分页、字体或版式预览。关闭后回到工作台原位置。

每组译文可点击“修改此组”填写要求，也可要求恢复原文分段。原文各段、当前译文、稳定段落 ID 与相邻上下文自动附带，进入项目串行队列，沿用项目模型、风格、术语和 RAG 选择。只修订和审校所选组；通过后从上一份已发布 DOCX 创建新版本，仅替换该组，其余组保持不变。未通过则保留旧版本，草稿和反馈在任务记录中下载。

新版本完成后面板提示“查看新版本”，不会自动切换。可选择历史版本阅读或下载，切换时保留段落位置。为防止后一次修改丢失前一次结果，同一版本链一次只允许一个待完成的段落修改，后续修改须基于最新版本；旧版本可读但不可继续提交修改。

原文使用稳定的 `p000001` 等 ID。Agent 可以将相邻正文合并为一段，或按目标语言风格拆成多段，并说明理由。程序校验原文完整覆盖、顺序、重复引用和结构边界；审校关注组内内容完整与合并/拆分是否恰当，不要求原译文段数相等。标题、列表、表格段落、题注以及含字段、对象或分节标记的段落保守地保持一对一。DOCX 空白段落及容器边界不跨越；PDF/TXT 只能保护提取文本中可识别的边界，无法保证还原未提取出的版面语义。

翻译采用“章节优先、长度兜底”：短章节连同内部子节整体翻译；超长章节优先按子节拆分，子节仍过长时再使用正文窗口。不同章不会为了凑满批次而合并。DOCX 使用标题样式及继承/显式大纲层级；PDF/TXT/Markdown 仅识别明确的 `#` 标题、`第一章 绪论`、`Chapter 1: Introduction` 等标记，不将普通编号列表推断成章节，代码围栏内不识别标题。没有可靠章节标记时按正文窗口处理。

批次软预算为一万原文字符，并同时检查原文与预计译文的合计 token 估算（默认 12,000，译文预留原文估算的 1.5 倍）。这是本地启发式预算，不是具体模型的精确 tokenizer 或上下文上限，也不包含风格、术语和 RAG 提示词的全部开销。不可再分的单个原文段落超软预算时单独处理并提示；仍保留四万字符的单段上限。每批附带章节路径、最多 800 字符的前后原文及前一组已审校译文，明确作为只读上下文，不重复翻译。进度显示章节路径和原文段落范围。

同一正文区跨长度窗口时，上一窗口最后一组暂不发布，留到下一窗口结合后文重新判断；不跨章节、子节或受保护结构边界延续。只能容纳单段的窗口直接提交该段，通过只读上下文衔接。每个批次继续使用已有翻译与审校循环，不增加章节摘要或额外逐段调用。术语证据通过同一组内的源段 ID 和目标段 ID 核实；ID 与译文版本一起使用，不能脱离版本引用。“原格式”导出保留当前已审校译文的分段，上传原件不变。新任务保存 `alignment.json`，支持多对多对应恢复；旧任务继续兼容一对一对应。

段落对应与版本关系持久化在 SQLite 的 `comparisons` 表，引用独立发布的 DOCX 快照。历史完整翻译首次打开时，会从已成功任务的原文批次快照和已发布 DOCX 恢复对应；记录不完整时明确提示不支持。普通对话生成的未审校文档不开放对照入口，以免错误匹配段落。

## 架构与边界

```text
Web 工作台
    │ HTTP + SSE
FastAPI ── SQLite（项目、任务、文件元数据、事件）
    │
单个调度器：项目间并行、项目内串行
    ├── Codex: exec --json / exec resume <明确的 session ID>
    ├── CodeBuddy: -p --output-format stream-json / --resume <session ID>
    ├── RAG: 多语言 embedding + 余弦检索
    └── 文档解析 / DOCX 导出 / 独立发布快照
```

- 不同项目的主任务并行运行，每个项目同时只执行一个主任务。对话、翻译、审校与排版按本项目的提交顺序执行；取消任务只影响指定项目，项目会话、模型、文件与事件独立。共享的本地向量模型仅在初始化和推理时加锁，Agent 调用不受该锁影响。
- 上下文保留在所绑定 CLI 的会话中；harness 只保存明确的 session ID，不通过 `--last` / `--continue` 猜测会话。审校与翻译使用同一 Agent 会话，属于自动自审，不等同于独立人工审校。
- 风格与术语在任务开始时快照，执行中编辑会用于后续任务。自动风格提取使用版本检查，检测到并发编辑时保留候选文件，不覆盖用户内容。
- 任务持久化；正常重启会继续排队任务，中断的运行任务标记为 interrupted，需重新提交。不会自动重复执行一个可能已修改文件的任务。
- 使用数据目录文件锁防止多 worker / 多服务同时运行；部署时保持 `workers=1`。停止任务会终止 CLI 进程组，正在执行的文档解析或向量计算须先结束当前调用。
- RAG 使用真正的语义向量，不把关键词匹配伪装成语义检索。索引保存在本地 JSON，适合首版与中小规模语料；没有另起向量数据库或 Agent 框架。

工作区目录：

```text
data/
  transmux.sqlite3
  published/<project-id>/<file-id>.docx   # 下载使用独立快照
  projects/<project-id>/
    AGENTS.md / CODEBUDDY.md
    style.md
    terms.json       # 目标语言术语及来源、删除记录
    mappings.json    # 审校通过的翻译对照及用户指定内容
    people.json      # 人名标准写法、别名、依据与确认状态
    glossary.md      # 旧版原文档案，保留但不注入新任务
    corpus/          # 参考语料原件和提取文本
    sources/         # 待翻译原件和提取文本
    rag/index.json   # 向量、来源、索引版本
    runs/<job-id>/   # 配置快照、召回依据、译文草稿、审校反馈
    outputs/         # Agent 可继续编辑的 DOCX
```

## 配置

通过启动进程的环境变量配置；不会自动加载 `.env`。

| 变量 | 默认值 / 用途 |
| --- | --- |
| `PORT` | `8000` |
| `TRANSMUX_HOST` | `127.0.0.1`，局域网部署时设为本机局域网 IP |
| `TRANSMUX_DATA` | `data`，建议使用持久化绝对路径 |
| `TRANSMUX_CODEX_BIN` | `codex`，可指定可执行文件绝对路径 |
| `TRANSMUX_CODEBUDDY_BIN` | `codebuddy`，可指定可执行文件绝对路径 |
| `TRANSMUX_CODEX_MODELS` / `TRANSMUX_CODEBUDDY_MODELS` | 可选，逗号分隔的候选模型 ID，覆盖本机自动发现列表；重启后生效 |
| `TRANSMUX_AGENT_TIMEOUT` | 单次 CLI 调用超时秒数，默认 `1800` |
| `TRANSMUX_EMBEDDING_URL` | 未设置时使用本地 sentence-transformers；设置时为 API 基础路径，例如 `http://127.0.0.1:8080/v1`，程序追加 `/embeddings` |
| `TRANSMUX_EMBEDDING_MODEL` | 默认 `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`；远程接口需设为该服务支持的模型 |

本地向量模型第一次执行 RAG 任务时按需加载、下载，服务冷启动不加载模型。远程向量服务会收到待检索段落与语料文本。更换向量模型或服务后，系统在下一次需要检索时自动重建索引。

本版本面向受信任的本机单用户，默认仅监听 `127.0.0.1`，无应用层登录。Codex 使用 `workspace-write` 沙箱；CodeBuddy headless 使用 `-y`，其进程拥有当前系统用户权限。项目目录和提示词不构成 CodeBuddy 的 OS 隔离边界。若接入不可信用户或公网，需在独立用户 / 容器中运行 Agent，并配置认证；不要直接暴露当前服务。

## 文档能力

DOCX 保留正文段落样式、标题层级、表格结构与非文本对象，替换正文及表格中的段落文本。译文沿用原段落首个文本 run 的格式，不保证混合字体、行内加粗、超链接文字、复杂域和分页完全一致；页眉页脚、批注、脚注及图片内文字暂不翻译。PDF 根据文本提取顺序生成新的 DOCX，不复刻 PDF 排版。扫描 PDF 需先 OCR。

首版审校针对每批文本的准确性、术语、风格和段落完整性，尚无整份渲染文档的视觉审校。长篇跨批次一致性仍依赖 Agent 上下文和术语文件。自动审校通过表示模型判定通过，不代表翻译质量的绝对保证。

## 验证

### 风格提取流水线（workflow 14）

提取不再按 8 段切批，也不再每批重写完整风格指南。每份文档独立规划，按约 10,000 输入 token 的启发式预算切分；输入达到半预算后优先在章节边界断开，短小章节可以合批。文档内均匀选择最多 24 个正文片段用于风格观察；术语和人名仍覆盖全部有效目标语言文本。单个超长提取块按最多 6,000 字符、优先空白或标点边界切片，保留原段落编号。预算不是模型精确 tokenizer，也不包含所有固定指令与输出开销。

PDF 仅对块内有明确特征的英文断行做保守连接，并去除多块边缘反复出现的短行；不改原文件，不猜测跨块段落关系。原文提取、语言判断与章节元数据按内容缓存。每批只返回简短风格观察、可核对的原文引用和术语/人名候选，最后统一生成最多 12 条风格规则。观察过多时分层汇总，保留证据链；引用存在不等于语义概括绝对正确，仍可人工修改。

提取及汇总使用独立 Agent 会话，不恢复或替换项目对话会话。缓存位于工作空间 `style-cache/`，按内容、目标语言、Agent、所选模型和流水线版本隔离；已成功批次可在失败重试时复用。模型留空时外部 CLI 默认模型变化无法自动识别，建议显式选择模型。未变化文档不重复调用 Agent；未变化的汇总和有效 RAG 索引也可复用。删除语料后，其风格观察不再参与下次汇总；已有术语、人名和历史仍保留，不自动删除用户积累的条目。

`requirements.md` 独立保存用户要求，风格区可展开编辑并查看历史。旧项目最近一次明确的人工/恢复/对话风格版本会保守地保留为要求；历史来源不明时保留现有指南。原先自动生成的指南不作为重新汇总的事实依据。直接手动编辑 `style.md` 表示将完整编辑结果指定为用户要求，界面有说明；可在用户要求区精简或清空。用户要求优先于自动指南，翻译时单独注入。

风格、术语、人名及提取完成标记先全部校验，再一起保存；普通写入失败会回滚文件和历史记录（不承诺进程崩溃时跨文件事务）。并发修改用户要求或风格时停止发布，缓存保留。提取成功与 RAG 状态分开：索引失败只需重试索引，不会再次标记风格待更新。

任务进度展示文档名、预计批次、新提取/复用数量；详细计划、观察、规则证据和各批校验报告保存在 `runs/<job>/`。这次升级不自动启动提取或覆盖已有指南。


### lambdax220 的 Tailscale 入口

同一 Tailnet 的设备可访问 `http://100.64.156.74:8765`，启用 MagicDNS 时也可访问 `http://lambdax220:8765` 或 `http://lambdax220.tailed8a37.ts.net:8765`。本机 hosts 将短名称映射到 loopback 时，请使用 Tailscale IP 或完整域名。

专用 Nginx 入口仅监听 `100.64.156.74:8765`，转发至现有 LAN 服务 `192.168.1.220:8765`。未开启 Funnel。配置在 `scripts/nginx-tailnet.conf`，用户服务模板在 `scripts/transmux-tailnet.service`，运行文件位于 `data/tailnet-proxy/`。服务已通过 `systemctl --user enable --now transmux-tailnet.service` 启用；查看状态或停用分别使用 `systemctl --user status transmux-tailnet.service`、`systemctl --user disable --now transmux-tailnet.service`。

代理先检查浏览器 Origin，再转换为后端地址，保留应用的跨站写入校验；支持上传和不缓冲的 SSE 进度流。若 Tailscale IP、机器域名或 LAN 地址变更，需更新配置，执行 `nginx -t -p /home/ider/workspace/TransMux/data/tailnet-proxy/ -c /home/ider/workspace/TransMux/scripts/nginx-tailnet.conf`，再重启该用户服务。该入口独立于应用部署，不会启动另一套任务调度器。

### 向量模型加载与长时间等待（workflow 15）

本地 embedding 仅使用已安装的模型目录或 Hugging Face 缓存快照，任务内不联网检查或下载模型。缺少完整缓存时明确报错，可提前准备模型或配置 `TRANSMUX_EMBEDDING_URL`。加载本地模型前默认设置 `HF_HUB_OFFLINE=1`，并使用 `local_files_only=True` 及具体缓存目录，避免网络不可达时模型库连续重试。

等待其他本地向量计算释放锁的上限为 120 秒；这不是所有推理操作的统一硬超时。页面当前阶段超过 60 秒时显示醒目等待提示，异常返回后显示实际原因，支持停止与重试。
